## 功能性缺口

### 章节数为 0（最重要）

```
涟城库：记录 58 · 关系 27 · 历史 65 · 章节 0
```

章节记录的**机制全部就绪**：

- `enderwriter_chapter` 工具存在
- `at_chapter` 检索过滤已实现并测试通过
- `chapters` 表结构完整

但没有真实数据喂进去。后果：

- 时间轴检索（`at_chapter`）没有数据可过滤
- 伏笔的 `planted_chapter` 无法自动补
- 「上次写到哪」查不到

**待办**：把设定稿里 845 行的「逐章细纲」抽成章节骨架（只取章号和标题，不导正文）。

### 检索后编辑会丢展开状态

`editing` / `historyFor` 用行 `key` 匹配。如果保存后列表重新加载，所有行会收起。这是可接受的行为，但不够顺手。

### state 表为空

一致性检查（R1-R5）依赖 state 表（alive / injury / owner / realm / location）。

当前涟城库 **0 行**。所以 `check` 返回：

```
【一致性检查】未执行 —— 这个作品库里没有可用于核对的设定事实
```

这是**正确行为**（不假装通过），但意味着五条规则一次都没真正跑过。

**补法**：用 `enderwriter_writeback` 写入 state，或在设定正文里写「左手受刀伤」这类可识别表述。

## 技术债

### aliases 表是空的

称呼归一（"老白" → "白杨"）机制存在，但没有自动抽取，需要手动 `link_alias()`。

影响：检索「作战等级」找不到写成「战力等级」的条目。

### R5 是启发式

```
残兽R5 只报 low 严重度，用来提示复核，不该据此阻断写作。
```

地名识别靠后缀（城/山/关/寨…），会有漏报和误报。7 个测试用例全过，但真实语料上未充分验证。

### 图层猜测有限

导入器的 `LAYER_HINTS` 只覆盖常见词。没列出的关键词会落到默认 `world`。

### medium 摘要按 token 截断

`clip_tokens` 从头截，不保证在句子边界停。可能切在半句话中间。

## 插件层

### HTTP 端点与 RPC 并存

面板走 HTTP（该 DSH 版本 Client 没有 host 服务），工具走进程内调用。两套路径。

**风险**：两套表靠人工同步。已加自动核对（对比 Client 调用 / Host 端点 / Python op 三张表的差集），但仍需每次跑。

### 面板无实时刷新

数据变化后要手动点「刷新」。没有订阅机制。

### 长正文渲染

`clip_tokens(2000)` 截断后展示。极长条目（5000+ 字）看全文要靠「展开」。

## 环境问题（DSH 侧）

### 上游模型报错

```
The `reasoning_content` in the thinking mode must be passed back to the API
```

`dsh-our-free-model` 插件在转发 thinking 模式的请求时，没有把 `reasoning_content` 回传给上游。属于该插件的问题，不是末影箱的。`src/stream.js` 里有 `REASONING_FIELDS` 处理逻辑，但显然有遗漏路径。

### 上下文超限

```
more tokens than this model's maximum context length
```

长会话累积导致的模型窗口溢出。`/compact` 或开新对话解决。
