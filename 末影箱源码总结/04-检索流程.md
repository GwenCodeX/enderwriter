# 04 · 检索流程

从一次查询到三档结果的完整链路。

---

## 入口

```python
from enderwriter.retrieval import MemoryKeeper

keeper = MemoryKeeper(chest, default_budget=800)
result = keeper.search({
    "entities": ["残兽"],
    "query_context": "写第 42 章，需要残兽的分级规则",
    "at_chapter": "ch_042",        # 按叙事位置过滤
    "budget": 800,
})
```

---

## 七个步骤

### 1. 入参校验

```python
C.validate(req, C.schema("search_memory_tool"))
# 非法请求在这里抛 SchemaError
```

Schema 要求：

```json
{
  "required": ["entities"],
  "properties": {
    "entities": {"array", "minItems": 1},
    "query_context": {"string"},
    "layers": {"array", "enum": [七格]},
    "budget": {"integer", "1..8000"},
    "at_chapter": {"string"}
  }
}
```

### 2. 实体归一化

```python
entities, alias_map, canonical_aliases = self._normalize(entities_in, trace)
```

把别名映射到标准名：

```
"老白" → "白杨"
"异兽" → "残兽"（如果配了别名）
```

同时记录 `ctx_set`（已经在上下文里的实体），这些不重复返回正文。

### 3. 多通道召回

四条通道并行，结果按 `(layer, entity)` 合并：

```python
channels: dict[tuple[str, str], {
    "record": Record,
    "channels": set[str],        # 哪些通道命中
    "scores": dict[str, float],  # 各通道得分
    "exact": bool,
}]
```

#### 通道 A：关键词倒排

```python
search_terms(query) -> list[Hit]
# 1. 切二元组
# 2. 查 terms 表
# 3. 分数 = weight × IDF / 长度归一
```

#### 通道 B：向量

```python
search_vector(query) -> list[Hit]
# 1. embed(query) → 256 维
# 2. 与库里每条记录算余弦
# 3. 高于阈值的返回
```

#### 通道 C：关系图

```python
search_graph(seeds, hops=2) -> list[Hit]
# 从种子实体 BFS
# 深度 d 的邻居得分 1/(d+1)
# 种子本身得 1.0
```

#### 通道 D：精确匹配

实体名完全相等 → `exact = True`，得分额外 ×2。

#### 二跳弱关联

```python
# 种子的邻居的邻居，且正文无重叠
# 标记为 "weak"，只用来做 low 档探索
```

### 4. 分档

```python
bands, superseded = self._classify(channels, ctx_set, trace, at_chapter=at)
```

判定顺序：

```python
if is_superseded(rec):           # 已废止
    superseded.append(rec.entity)
    continue                     # 不入任何档

if not _chapter_gate(rec, at_no):  # 未来设定
    future += 1
    continue

if exact 或 len(evidence) >= 2:   → high
elif "weak" in channels:          → low
elif evidence 且 confidence >= 门槛: → medium
elif confidence >= 弱底线:         → low
else: 丢弃                         # 纯向量噪声
```

### 5. 预算分配

```python
BAND_RATIOS = {"high": 0.50, "medium": 0.35, "low": 0.15}
```

#### high 档

```python
for item in bands["high"]:
    full = self._render(rec, item, ...)     # 完整正文
    if cost > cap: break
    out["high"].append(hit)
```

用不完的预算流给 medium。

#### medium 档（本轮重写）

```python
# 关键改动：不再把预算平均切碎
# 之前：22 条候选 / 280 预算 → 每条 12 tokens ≈ 8 汉字
#       而条目名就有 10~15 字，摘要比标题还短

cap_initial = cap = min(caps["medium"] + 剩余, total_left)
for item in bands["medium"]:
    fair = cap // max(1, left_count)       # 公平份额
    share = min(max(fair, _MEDIUM_MIN_SHARE), cap)
    if share < _MEDIUM_FLOOR_SHARE:        # 剩余预算不够说清一句话
        skipped += 1
        continue
    content = C.clip_tokens(full, share)
```

参数：

```python
_MEDIUM_MIN_SHARE = 80     # 可读下限 ≈ 55 汉字
_MEDIUM_FLOOR_SHARE = 40   # 绝对下限，低于此不再切
```

效果：

```
之前：22 条 × 8 字 = 「残兽强度分级（…」
现在： 6 条 × 88 字 = 「残兽强度分级（world 层 · 残兽机制之二）：
                      残兽的强度被分为 12 个等级，最低为 1 级…」
```

**三条看得懂的，比二十二条看不懂的有用。**

#### low 档

```python
limit = 2 if cap >= 40 else 1
per = max(20, min(60, cap // limit))
# 只抽样 1~2 条，极短摘要
```

### 6. low 抽样去重

```python
_apply_seen_low(buckets, bands, seen_low, ...)
```

同一写作周期内已经抽过的 low 条目不重复抽，避免每次检索都返回同样的边缘内容。

### 7. 记录使用 ★ 本轮新增

```python
for h in (*high, *medium, *low):
    self.chest.bump_usage(h.layer, h.entity, commit=False)
self.chest.conn.commit()
```

**语义**：一条记忆被检索进上下文 = 被用过 = 标记为已回收归档。

三个约束：

1. **只标记，不删除**（设定集里的条目随时可能再被引用）
2. 不写 history、不推版本号（使用记录是元数据）
3. 失败静默（统计不该影响检索本身）

## 上下文实体不重复占预算

```python
hit.in_context = rec.entity in ctx_set
# 渲染时 content 变成 "已在上下文"
# 实际占用只有这个提示串的 token
```

这样"已经在上下文里的部分"不会重复消耗预算。

## 按叙事位置检索 ★ 本轮新增

```python
result = keeper.search({
    "entities": ["白杨"],
    "at_chapter": "ch_010",
})
```

过滤逻辑：

```python
def _chapter_gate(rec, at_no):
    vf = rec.data.get("valid_from")
    if vf and chapter_index(vf) > at_no:
        return False        # 这条设定在第 10 章还不成立
    vu = rec.data.get("valid_until")
    if vu and chapter_index(vu) < at_no:
        return False        # 这条设定在第 10 章已经失效
    return True
```

实测：

```
ch_010 可见：['旧设定']     ← 早期设定（valid_until=ch_040）
ch_050 可见：['新设定']     ← 后期设定（valid_from=ch_041）
```

**这是长篇小说的核心需求**：同一条设定随剧情演变，写第 10 章不该看到第 50 章才成立的结论。
