## 数据流

### 写作时（读路径）

```
作者："白杨现在什么状态"
  ↓
Orchestrator 拆成检索请求
  ├── entities: ["白杨"]
  ├── query_context: "写作第 42 章"
  ├── at_chapter: "ch_042"          ← 按叙事位置过滤
  └── budget: 800 tokens
  ↓
MemoryKeeper.search()
  ├── 1. 实体归一化（别名 → 标准名）
  ├── 2. 多通道召回
  │     ├── 关键词倒排（CJK 二元组）
  │     ├── 向量相似（256 维哈希）
  │     ├── 关系图 BFS（1-2 跳）
  │     └── 精确匹配
  ├── 3. 分档
  │     ├── high   精确命中或多通道 → 完整正文，占 50%
  │     ├── medium 单通道 → 摘要，占 35%
  │     └── low    二跳弱关联 → 极短摘要，占 15%
  └── 4. 过滤
        ├── 已废止（superseded）→ 不返回，只报名字
        └── 未来设定（valid_from > 当前章）→ 不返回
  ↓
返回三档结果 + 总 token 数
```

### 写完一章（写路径）

```
作者写完第 42 章
  ↓
① enderwriter_chapter 记录章节（推进"当前章节"）
  ↓
② enderwriter_writeback 回写事实变化
  ├── 更新 records（版本 +1，旧版进 history）
  ├── 更新 state 表（alive / injury / owner / realm / location）
  └── 检测矛盾（时间倒错 / 能力违规 / 称呼漂移）
  ↓
③ enderwriter_patrol 伏笔巡检
  ├── overdue   超期未回收
  ├── stale     长期未强化
  └── unplanned 没有回收计划的伏笔（巡检无法判断）
```

## 四个索引

末影箱不是简单 KV 存储。同一条记录同时进四个索引：

| 索引 | 表 | 作用 | 查询方式 |
|---|---|---|---|
| **倒排** | `terms` | 关键词召回 | CJK 二元组 + IDF 加权 |
| **向量** | `records.embedding` | 语义近似 | 256 维哈希向量余弦 |
| **关系图** | `edges` | 多跳扩散 | BFS，`1/(depth+1)` 衰减 |
| **状态表** | `state` | 结构化事实 | 精确键值 |

为什么要四个：单个索引都有盲区。

- 倒排：查「残兽」找不到写成「异兽」的条目
- 向量：能处理近义，但会把不相干的也拉进来
- 关系图：能沿「残兽 → 分级」扩散，但需要先有关系
- 状态表：精确，但只能查预先结构化的字段

**多通道命中有额外加成**（每多一个通道 +15%），所以同时被倒排和向量命中的条目排得更前。

## 三档预算

这是检索的核心机制。

```
总预算 800 tokens
├── high   50% = 400  完整正文
├── medium 35% = 280  摘要（但有可读下限 80 tokens/条）
└── low    15% = 120  极短摘要
```

**关键约束**：high 档用不完的预算会流给 medium，medium 用不完的流给 low。最终总开销不超过预算。

**medium 档的可读下限**是本轮修的：

```
之前：22 条候选、280 预算 → 每条 12 tokens ≈ 8 个汉字
      而条目名本身就有 10~15 字，摘要比标题还短

现在：每条至少 80 tokens（约 55 汉字），
      预算不够就少返回几条 —— 三条看得懂的比二十二条看不懂的有用
```

## 上下文预算（编排器）

写作时的完整上下文分配：

| 优先级 | 占比 | 内容 |
|---|---|---|
| P0 | 30% | 当前章节细纲 |
| P1 | 30% | 相关设定（检索结果） |
| P2 | 20% | 前文摘要 |
| P3 | 15% | 风格样本 |
| P4 | 5% | 兜底（吸收浮点余数） |

总计占窗口的 **70%**，留 30% 给生成。

## 分层

```
作品库（每个对话/作品一套）
├── character      人物
├── world          世界观
├── timeline       时间线
├── foreshadowing  伏笔
└── item           物品

全局文学库（跨作品）
└── style          写作经验

技术库（跨项目）
├── style          技术案例（事故复盘）
└── assertion      技术断言（可执行规则）
```

`alias` 是内部使用的称呼格，不对外。

## 会话隔离

默认行为：**一个对话就是一套独立记忆**。

```python
session_work("session-f9e25f1f-2111-4142-...")
  → "对话-99017a6c"        # 取末 8 位字母数字

resolve_work(work, session_id)
  → 显式 work > 会话作品 > ""
```

想跨对话共享某部作品的设定，显式传 `work="涟城"`。

## 模块依赖

```
bridge.py（协议层，34 个 op）
  ├── memory.py      分层路由
  │     └── chest/store.py   存储
  ├── retrieval.py   检索
  │     └── chest/store.py
  ├── review.py      一致性规则
  ├── writeback.py   回写与巡检
  ├── guard.py       断言引擎
  ├── relations.py   关系抽取
  ├── export.py      整理与导出
  └── importer.py    文档导入

orchestrator.py（编排，独立于 bridge）
  ├── retrieval.py
  ├── llm.py
  └── writeback.py

common.py    被所有模块依赖（契约层，不可改）
lexicon.py   被 retrieval / relations 依赖
embed.py     被 chest 依赖
```

**没有任何循环依赖。** `common.py` 是唯一的公共基础，其余模块单向引用。
