### 废止判定：只认显式标记

```python
# 试过用正文关键词"已废止""已作废"自动判断，实测 6 条全是误判：
#   战力牌级表正文写着「字母记法…已废止，唯一有效的体系就是本条」
#   → 它是现行版，不是被废止的那个
#
# 真相：一条记录说「X 已废止」时，它通常正是取代 X 的那条。
_SUPERSEDED_STATUS = frozenset({"superseded", "deprecated", "obsolete"})

def is_superseded(rec):
    return rec.data.get("superseded") is True or \
           rec.data.get("status") in _SUPERSEDED_STATUS
```

**结论：猜不如让人声明。**

## guard.py · 技术断言引擎（434 行）★ 本轮新增

把事故复盘变成可机械判定的规则。

### 两种触发方式

```python
# 1. 代码特征（写的时候抓）
rule        = "重载 operator== 里不得用 a == null 判空"
detect_all  = ["operator ==", "== null"]     # 全部出现才命中
detect_not  = ["ReferenceEquals"]            # 出现这个说明已写对，不报警

# 2. 任务意图（动手之前抓）
when = ["回写 DLL", "Assembly-CSharp"]
```

`when` 覆盖了"流程性教训"——源码里没有特征，但你知道自己正要干这件事。

### 校验器：挡住会误报的断言

```python
def validate(rule, detect_all, when=(), allow_single=False):
    # 至少 2 个条件（单泛化条件会让断言对几乎所有代码报错）
    # 拒绝通用词（void Update / for ( / if ( ...）
    # 拒绝太短的（< 3 字符）

# 为什么严格：
# 用模型抽断言会产出两类废品：
#   ["operator =="]              条件太宽
#   ["Update", "snInfo =="]      绑死变量名
# 这两类都会让断言持续误报 → 被无视 → 整个功能被关掉
```

### 使用

```python
hits = guard(chest, code_text, task="回写 DLL")
# → [GuardHit(assertion, matched, line=3, via="code")]
```
