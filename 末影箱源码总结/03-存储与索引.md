# 03 · 存储与索引

数据全部落在 SQLite，无外部依赖。

---

## 表结构全貌

```sql
meta          -- 库级元信息（作品名、当前章节、面板开关）
records       -- 主表：当前版本
history       -- 版本历史（追加式，永不覆盖）
terms         -- 倒排索引
records.embedding  -- 向量（存在主表里）
edges         -- 关系图
state         -- 结构化事实
aliases       -- 称呼归一
chapters      -- 章节正文
usage         -- ★ 使用记录（回收归档）
feedback      -- ★ 反馈记录（规则误报）
```

## records · 主表

```sql
CREATE TABLE records (
    layer       TEXT NOT NULL,
    entity      TEXT NOT NULL,
    content     TEXT NOT NULL,
    data        TEXT NOT NULL DEFAULT '{}',   -- JSON
    version     INTEGER NOT NULL DEFAULT 1,
    last_updated TEXT NOT NULL,
    chapter_id  TEXT,
    embedding   BLOB,                          -- 256 维 float32
    PRIMARY KEY (layer, entity)
);
```

### data 里放什么

不同图层用不同的键：

```json
// 伏笔
{"status":"planted", "planted_chapter":"ch_001",
 "planned_resolve":"ch_050", "reinforced_chapters":[]}

// 技术断言
{"detect_all":["operator ==","== null"], "detect_not":["ReferenceEquals"],
 "when":[], "fix":"...", "consequence":"...", "severity":"high"}

// 已废止标记
{"superseded":true, "superseded_note":"被数值牌级制取代"}

// 时间轴
{"valid_from":"ch_001", "valid_until":"ch_040"}

// 导入标记
{"imported":true, "source":"设定稿.txt"}
```

**`data` 不参与版本比对**，只随 `records` 一起更新。

## history · 版本历史

```sql
CREATE TABLE history (
    layer      TEXT NOT NULL,
    entity     TEXT NOT NULL,
    version    INTEGER NOT NULL,
    content    TEXT NOT NULL,
    data       TEXT NOT NULL,
    chapter_id TEXT,
    updated_at TEXT NOT NULL,
    change     TEXT           -- 变更说明，如 "revert to v1"
);
CREATE INDEX idx_history ON history(layer, entity, version);
```

### 为什么追加式

```
AI 覆写设定 → v1 → v2 → v3    旧内容全部保留
回滚到 v1   → 写入 v4         v1~v3 仍在
```

**回滚本身也能再回滚。** 这保证了「AI 可以放心改写，人随时能查」。

查询：

```python
chest.history("character", "白露")
# → [Record(v1, ...), Record(v2, ...)]
```

## terms · 倒排索引

```sql
CREATE TABLE terms (
    term   TEXT NOT NULL,
    layer  TEXT NOT NULL,
    entity TEXT NOT NULL,
    weight REAL NOT NULL DEFAULT 1.0
);
CREATE INDEX idx_terms_term ON terms(term);
```

### 切词：CJK 二元组

中文没有空格，用二元组（bigram）：

```
"残兽强度分级"
→ ["残兽", "兽强", "强度", "度分", "分级"]
```

优点：无需词典，召回率高。
缺点：会产生无意义组合（"兽强"），靠 IDF 压制。

### 权重计算

```python
term_weights(content, entity=entity) -> dict[str, float]
# 实体名里的词 ×2
# 正文词按 TF 计算
# 查询时再乘 IDF 和长度归一
```

### 重建时机

每次 `upsert` 都会先 `DELETE` 该记录的词条再重建——保证与内容一致。

### 为什么用哈希而不是真模型

- 无第三方依赖（不需要 numpy / sentence-transformers）
- 确定性：同样输入永远同样输出
- 快：微秒级

代价：语义能力弱于真 embedding，但对"同一批设定内部的相似度"够用。

## edges · 关系图

```sql
CREATE TABLE edges (
    src        TEXT NOT NULL,
    rel        TEXT NOT NULL,
    dst        TEXT NOT NULL,
    chapter_id TEXT,
    data       TEXT NOT NULL DEFAULT '{}',   -- {"weight": 5, "auto": true}
    PRIMARY KEY (src, rel, dst)
);
CREATE INDEX idx_edges_src ON edges(src);
CREATE INDEX idx_edges_dst ON edges(dst);
```

### 关系类型

| rel | 含义 | 来源 |
|---|---|---|
| `part_of` | 从属 | 正文"属于/的一部分" 或名字前缀 |
| `owned_by` | 持有 | 正文"由 X 保管" |
| `supersedes` | 取代 | 正文"废止/取代" |
| `mentions` | 提及 | 默认 |

## state · 结构化事实

```sql
CREATE TABLE state (
    entity     TEXT NOT NULL,
    key        TEXT NOT NULL,
    value      TEXT NOT NULL,
    chapter_id TEXT,
    version    INTEGER NOT NULL DEFAULT 1,
    updated_at TEXT NOT NULL,
    PRIMARY KEY (entity, key)
);
```

### 用到的键

| key | 值 | 被哪条规则用 |
|---|---|---|
| `alive` | `true` / `false` | R1 死而复生 |
| `injury` | `"左手"` | R2 伤情违反 |
| `owner` | `"裴照"` | R3 持有者违反 |
| `realm` | `"白牌"` | R4 境界回退 |
| `location` | `"涟城"` | R5 位置瞬移 |

**这张表是空的时，一致性检查就无从判定。** 所以 `check` 在无事实时返回 `executed=False` 而不是"通过"。

## aliases · 称呼归一

```sql
CREATE TABLE aliases (
    alias     TEXT PRIMARY KEY,
    canonical TEXT NOT NULL
);
CREATE INDEX idx_aliases_canon ON aliases(canonical);
```

用途：`resolve_entity(name)` 在检索前把别名映射到标准名。

```
"老白" → "白杨"
"残兽" → （保持）
```

**当前是空的** —— 没有自动抽取机制，需要手动 `link_alias()`。

## usage · 使用记录 ★ 本轮新增

```sql
CREATE TABLE usage (
    layer       TEXT NOT NULL,
    entity      TEXT NOT NULL,
    hit_count   INTEGER NOT NULL DEFAULT 0,
    first_hit_at TEXT,
    last_hit_at TEXT,
    archived    INTEGER NOT NULL DEFAULT 0,
    archived_at TEXT,
    note        TEXT NOT NULL DEFAULT '',
    PRIMARY KEY (layer, entity)
);
```

### 语义：回收归档，不是删除

```
检索命中 → hit_count +1，archived = 1
```

**末影箱在文学场景下兼当设定集**，任何设定都可能在几百章后被再次引用。所以：

- 只有"未使用 / 已使用（归档）"两种状态
- **没有"过期删除"**
- 归档不影响检索，只是面板上的绿色徽章

### 为什么不放 records.data

两个理由：

1. `data` 参与版本管理，每次命中都 bump version 会把 history 撑爆
2. 使用记录是"关于记忆的元数据"，生命周期与内容不同

## feedback · 反馈记录 ★ 本轮新增

```sql
CREATE TABLE feedback (
    id      INTEGER PRIMARY KEY AUTOINCREMENT,
    kind    TEXT NOT NULL,     -- assertion | rule
    ref     TEXT NOT NULL,     -- 断言 id 或 R1..R5
    verdict TEXT NOT NULL,     -- fp（误报）| tp（真问题）
    note    TEXT NOT NULL DEFAULT '',
    at      TEXT NOT NULL
);
CREATE INDEX idx_feedback_ref ON feedback(kind, ref);
```

### 作用：让规则变准

```python
stats = chest.feedback_stats("assertion")
# {"assertion:unity-operator-eq-null": {"fp":2, "tp":0, "total":2, "fp_rate":1.0}}
```

护栏输出时自动降级：

```
⚠ 其中 unity-operator-eq-null 历史上多次被判为误报，命中仅供参考。
```

**降级条件**：累计 ≥2 次且误报率 ≥50%。单次误报不轻易否定一条断言。

## 索引策略总结

| 索引 | 数据量 | 查询复杂度 | 适用 |
|---|---|---|---|
| terms | 词条数 ≈ 内容字数 × 0.8 | O(词条数) | 关键词精确召回 |
| embedding | 每条一个向量 | O(条目数 × 256) | 语义近似 |
| edges | 强边数 | O(分支^深度) | 多跳扩散 |
| state | 每条实体数 | O(1) | 结构化精确查询 |

**四路都有盲区，所以合并使用。** 多通道命中 +15% 加成。
